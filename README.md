# Neovim-конфиг для Go-разработки

Этот документ описывает, что делает каждый файл конфига и как этим пользоваться.
Рассчитан на человека, который только начинает работать с Neovim.

## 1. Минимум понятий Neovim

- **Режимы.** Neovim - модальный редактор:
  - **Normal** (по умолчанию) - навигация и команды. Буквы здесь не печатаются, а выполняют действия.
  - **Insert** (`i`, `a`, `o`) - обычный ввод текста. Выход обратно в Normal: `Esc`.
  - **Visual** (`v`, `V`) - выделение текста.
  - **Command-line** (`:`) - ввод команд: `:w` (сохранить), `:q` (выйти), `:wq`, `:q!` (выйти без сохранения).
- **Нотация клавиш:** `<C-h>` = Ctrl+h, `<S-l>` = Shift+l, `<CR>` = Enter, `<Esc>` = Escape.
- **Leader** - префиксная клавиша для пользовательских сочетаний. Здесь это **пробел**.
  `<leader>ff` значит нажать по очереди `Space`, `f`, `f` (не одновременно).
- **Буфер** - открытый в памяти файл. **Окно** - область экрана, которая показывает буфер.
  Открытых буферов может быть много, а видно только те, что в окнах.
- **Плагин** - код на Lua, который расширяет Neovim. Сам конфиг тоже написан на Lua.
- **LSP (Language Server Protocol).** Neovim сам не понимает Go. Этим занимается отдельная
  программа - языковой сервер (для Go это `gopls`). Neovim отправляет ей запросы и получает
  ответы: где определение функции, какие есть ошибки, что предложить в автодополнении.
- **Treesitter** - парсер, который строит синтаксическое дерево файла. Используется для
  точной подсветки кода и расчёта отступов.
- **Встроенная справка:** `:help <тема>` (например `:help motion`). `:Tutor` - встроенный
  интерактивный учебник, его стоит пройти в первую очередь.

### Самые нужные команды Normal-режима

| Клавиши             | Действие                                           |
|---------------------|----------------------------------------------------|
| `h` `j` `k` `l`     | влево / вниз / вверх / вправо                      |
| `w` / `b`           | следующее / предыдущее слово                       |
| `gg` / `G`          | начало / конец файла                               |
| `0` / `$`           | начало / конец строки                              |
| `dd` / `yy` / `p`   | удалить строку / скопировать строку / вставить     |
| `u` / `<C-r>`       | отменить / повторить                               |
| `/текст`, `n`, `N`  | поиск, следующее / предыдущее совпадение           |
| `<C-o>` / `<C-i>`   | назад / вперёд по истории переходов (после `gd`)   |

## 2. Файлы репозитория и как идёт загрузка

```
~/.config/nvim/
├── init.lua                 -- точка входа, подключает всё остальное
├── lazy-lock.json           -- зафиксированные версии плагинов (данные, не код)
├── README.md                -- этот документ
└── lua/
    ├── config/              -- настройки самого редактора, без плагинов
    │   ├── options.lua      -- опции редактора
    │   ├── keymaps.lua      -- глобальные горячие клавиши
    │   ├── autocmds.lua     -- автокоманды (реакции на события)
    │   └── lazy.lua         -- установка и запуск менеджера плагинов
    └── plugins/             -- описания плагинов, их читает lazy.nvim
        ├── ui.lua           -- тема, статусбар, дерево файлов
        ├── lsp.lua          -- mason, gopls, conform (форматирование)
        ├── completion.lua   -- nvim-cmp (автодополнение), сниппеты
        ├── treesitter.lua   -- подсветка и отступы
        ├── telescope.lua    -- поиск файлов и текста
        └── git.lua          -- gitsigns, neogit
```

### 2.1. Где Neovim ищет файлы: runtimepath

При старте Neovim выполняет `init.lua` из папки конфига (`~/.config/nvim`). Всё остальное
подключается уже из него, напрямую или через плагины.

Файлы связаны друг с другом не через полные пути, а через **runtimepath** (`:set rtp?`) -
список папок, в которых Neovim ищет файлы по стандартным подпапкам (`lua/`, `ftplugin/`,
`plugin/`, `colors/` и т.д.). В этом списке есть:

- `~/.config/nvim` - этот репозиторий;
- папка каждого загруженного плагина (`~/.local/share/nvim/lazy/<плагин>`);
- `$VIMRUNTIME` - встроенные файлы самого Neovim;
- `~/.local/share/nvim/site` - сюда ставятся парсеры treesitter.

### 2.2. Два способа, которыми подключаются файлы

1. **`require("a.b")`** - явное подключение Lua-модуля. Ищет `lua/a/b.lua` (или
   `lua/a/b/init.lua`) во всех папках runtimepath; точки в имени заменяются на папки.
   Модуль выполняется **один раз**, результат кэшируется: повторный `require` вернёт тот же
   объект, не выполняя файл заново. Так `init.lua` подключает файлы из `lua/config/`,
   lazy.nvim подключает файлы из `lua/plugins/`, а конфиг вызывает сами плагины
   (`require("gitsigns")`, `require("cmp")`).
2. **Специальные папки**, файлы из которых Neovim выполняет сам по событиям. Например,
   `ftplugin/<тип файла>.lua` выполняется каждый раз, когда открывается файл этого типа, и его
   никто не подключает через `require`. В этом репозитории таких папок нет, но они есть у
   самого Neovim и у плагинов: табы для Go ставит встроенный `$VIMRUNTIME/ftplugin/go.vim`
   (`noexpandtab`, `shiftwidth=0` - то есть ширина отступа равна `tabstop`). Проверить,
   откуда взялась опция: `:verbose set shiftwidth?`. Если понадобится переопределить что-то
   поверх встроенного ftplugin, файл нужно класть в `after/ftplugin/go.lua`: папка `after/`
   выполняется после встроенных файлов.

### 2.3. Что делает каждый файл

**`init.lua`** - точка входа. Четыре `require` по порядку и одна опция в конце. Порядок важен:
`options` идёт первым, потому что в нём задаётся leader-клавиша, а она должна быть определена
до того, как любой файл создаст сочетание с `<leader>` (сочетание запоминает leader в момент
создания).

**`lua/config/options.lua`** - только выставляет опции и ничего не возвращает.
`vim.opt.X = ...` - то же самое, что команда `:set X=...`; `vim.g.X` - глобальная переменная
(так задаётся leader).

**`lua/config/keymaps.lua`** - глобальные сочетания через `vim.keymap.set(режим, клавиши, действие)`
(`"n"` - Normal-режим). Файл выполняется **до** загрузки плагинов, и это нормально: действие
`<cmd>Telescope find_files<CR>` - это просто текст команды, он выполнится при нажатии, когда
плагин уже загружен. Здесь только клавиши общего назначения. Клавиши, привязанные к плагинам,
лежат рядом с самими плагинами: LSP в `lsp.lua`, git в `git.lua`.

**`lua/config/autocmds.lua`** - автокоманды: "при событии X выполнить функцию".
Здесь одна: на событие `TextYankPost` (текст скопирован) подсветить скопированное.

**`lua/config/lazy.lua`** - запуск менеджера плагинов, в два шага:
1. *Bootstrap.* Если в `~/.local/share/nvim/lazy/lazy.nvim` ничего нет, клонирует lazy.nvim
   с GitHub. Затем добавляет эту папку в начало runtimepath, иначе `require("lazy")` не нашёл бы его.
2. `require("lazy").setup("plugins", {...})` - строка `"plugins"` означает "импортируй все
   модули из `lua/plugins/`". Второй аргумент - настройки самого lazy.nvim.

**`lua/plugins/*.lua`** - каждый файл возвращает (`return { ... }`) список спецификаций плагинов.
Важно понимать: **эти файлы сами ничего не настраивают**, они только описывают, что lazy.nvim
должен сделать. Код внутри `config = function() ... end` выполнится позже, в момент загрузки
плагина. Имена и разбиение на файлы произвольные, только для удобства: lazy.nvim склеивает все
файлы в один общий список. Поэтому:
- один и тот же плагин можно упомянуть в нескольких файлах. `plenary.nvim` указан в
  `telescope.lua`, `ui.lua` и `git.lua`, а установлен будет один раз;
- файлы могут зависеть друг от друга. `lsp.lua` вызывает `require("cmp_nvim_lsp")`, а
  `cmp-nvim-lsp` - часть системы автодополнения из `completion.lua`. Это работает, потому что
  `cmp-nvim-lsp` указан в `dependencies` у `nvim-lspconfig`, и lazy.nvim загрузит его раньше.

**`lazy-lock.json`** - не код, его пишет lazy.nvim при установке и обновлении плагинов.
Хранит точный коммит каждого плагина, чтобы на другой машине установились те же версии.
Руками не редактируется, но его стоит хранить в git вместе с конфигом.

### 2.4. Что хранится вне репозитория

| Путь                                  | Содержимое                                     |
|---------------------------------------|------------------------------------------------|
| `~/.local/share/nvim/lazy/`           | скачанные плагины                              |
| `~/.local/share/nvim/mason/`          | программы, поставленные Mason (`gopls`)        |
| `~/.local/share/nvim/site/parser/`    | парсеры treesitter                             |
| `~/.local/state/nvim/`                | история отмен (`undofile`), логи (`lsp.log`)   |

Если что-то сломалось в плагинах, эти папки можно удалить: при следующем запуске всё
переустановится по `lazy-lock.json`.

### 2.5. Загрузка по шагам на примере `nvim main.go`

```
init.lua
├─ config.options      опции, leader
├─ config.keymaps      глобальные клавиши
├─ config.autocmds     подсветка при копировании
├─ config.lazy         lazy.setup("plugins") читает все lua/plugins/*.lua
│   ├─ сразу:           tokyonight (первым, priority), lualine, neo-tree, mason,
│   │                   mason-lspconfig, nvim-lspconfig (+ cmp-nvim-lsp),
│   │                   nvim-treesitter, telescope (+ fzf-native), gitsigns
│   └─ отложенно:       nvim-cmp (+ сниппеты)  -> при первом входе в Insert
│                       conform                -> при первом сохранении
│                       neogit                 -> по :Neogit / <leader>gs
└─ scrolloff = 999

открытие main.go (тип файла = go, событие FileType):
├─ встроенный ftplugin/go.vim: табы вместо пробелов
├─ treesitter.lua: включить подсветку treesitter
└─ vim.lsp.enable: запустить gopls -> событие LspAttach -> клавиши gd, K, ...
```

**Фаза 1 - `init.lua`** (до того как файл появится на экране):

1. `options`, `keymaps`, `autocmds` - выставляются опции, регистрируются клавиши и автокоманда.
2. `lazy.lua`: bootstrap, затем lazy.nvim собирает спецификации из всех `lua/plugins/*.lua`.
   При первом запуске он скачивает недостающие плагины и показывает окно прогресса.
3. lazy.nvim загружает **неленивые** плагины - у которых нет `event`, `cmd` или `keys` и которые
   указаны не только как чья-то зависимость. Первой идёт тема (`priority = 1000`), чтобы
   всё остальное сразу рисовалось в её цветах. Загрузка плагина = добавить его папку в
   runtimepath, до этого загрузить его `dependencies`, после этого выполнить настройку
   (`opts` -> `require(...).setup(opts)`, либо своя функция `config`). При этом:
   - `treesitter.lua` запускает установку парсеров и регистрирует автокоманду на `FileType`;
   - `lsp.lua` описывает и включает gopls, регистрирует автокоманду `LspAttach`, настраивает
     показ ошибок;
   - `git.lua` настраивает gitsigns и создаёт его клавиши;
   - `ui.lua` включает тему, статусбар и дерево файлов;
   - `telescope.lua` настраивает поиск.
4. Для **ленивых** плагинов lazy.nvim ставит "ловушки": автокоманду на `InsertEnter` для
   nvim-cmp, на `BufWritePre` для conform, заглушку команды `:Neogit` и клавишу `<leader>gs`
   для neogit. Сами плагины пока не загружены, поэтому запуск быстрее.
5. `init.lua` выставляет `scrolloff = 999`.

**Фаза 2 - открытие файла:**

6. Neovim определяет тип файла по расширению (`filetype=go`) и генерирует событие `FileType`.
   На него срабатывают несколько обработчиков:
   - встроенный `ftplugin/go.vim` включает табы;
   - автокоманда из `treesitter.lua` включает подсветку и отступы через treesitter;
   - `vim.lsp.enable("gopls")` запускает процесс `gopls` с корнем проекта в папке с `go.mod`.
7. gopls подключается к буферу -> событие `LspAttach` -> автокоманда из `lsp.lua` создаёт
   клавиши `gd`, `K`, `<leader>rn` и т.д. **только для этого буфера**. Затем gopls присылает
   ошибки и предупреждения.
8. gitsigns сравнивает файл с версией в git и рисует значки слева.

**Фаза 3 - по ходу работы:**

9. Первое нажатие `i` -> `InsertEnter` -> lazy.nvim загружает nvim-cmp и его зависимости
   (LuaSnip, friendly-snippets, cmp-buffer, cmp-path), выполняет `config` из `completion.lua`.
10. Первый `:w` -> `BufWritePre` -> lazy.nvim загружает conform и повторно генерирует
    событие, чтобы conform успел отформатировать файл до записи.
11. `<leader>gs` -> загружается и открывается neogit.

Посмотреть, что и когда загрузилось, можно в `:Lazy` (там же время загрузки каждого плагина)
и в `:Lazy profile`.

## 3. Базовые настройки (`lua/config/options.lua`)

| Опция                                   | Что делает                                                                 |
|-----------------------------------------|----------------------------------------------------------------------------|
| `mapleader = " "`                       | leader-клавиша - пробел                                                    |
| `number`, `relativenumber`              | номер текущей строки и относительные номера остальных (удобно для `5j`, `3dd`) |
| `mouse = "a"`                           | мышь работает во всех режимах                                              |
| `clipboard = "unnamedplus"`             | копирование и вставка идут через системный буфер обмена macOS              |
| `undofile`                              | история отмен сохраняется между сессиями                                   |
| `ignorecase` + `smartcase`              | поиск без учёта регистра, пока в запросе нет заглавных букв               |
| `signcolumn = "yes"`                    | колонка слева для значков (ошибки, git) всегда видна, текст не прыгает    |
| `updatetime = 250`                      | быстрее срабатывают события "курсор стоит на месте" (обновление git-значков) |
| `timeoutlen = 300`                      | сколько мс ждать следующую клавишу в сочетании                             |
| `splitright`, `splitbelow`              | новые окна открываются справа / снизу                                      |
| `termguicolors`                         | 24-битные цвета (нужно для темы)                                           |
| `cursorline`                            | подсветка текущей строки                                                   |
| `wrap = false`                          | длинные строки не переносятся                                              |
| `inccommand = "split"`                  | при `:%s/старое/новое/` результат замены виден заранее                     |
| `tabstop`/`shiftwidth` = 4, `expandtab` | отступ 4 пробела (для Go переопределено на табы)                           |
| `list` + `listchars`                    | показывает табы как `» `, пробелы в конце строки как `·`                   |

Для Go-файлов табы вместо пробелов ставит встроенный ftplugin Neovim (`gofmt` требует табы),
см. раздел 2.2.

`lua/config/autocmds.lua` - кратко подсвечивает только что скопированный (yank) текст.

## 4. Горячие клавиши

### Общие (`lua/config/keymaps.lua`)

| Клавиша        | Действие                                   |
|----------------|--------------------------------------------|
| `<Esc>`        | убрать подсветку результатов поиска        |
| `<leader>e`    | открыть / закрыть дерево файлов            |
| `<leader>ff`   | поиск файла по имени                       |
| `<leader>fg`   | поиск текста по всему проекту (live grep)  |
| `<leader>fb`   | список открытых буферов                    |
| `<leader>fh`   | поиск по встроенной справке                |
| `<C-h/j/k/l>`  | перейти в окно слева / снизу / сверху / справа |
| `<S-l>` / `<S-h>` | следующий / предыдущий буфер            |

### LSP (работают только в файлах, к которым подключился `gopls`)

| Клавиша       | Действие                                     |
|---------------|----------------------------------------------|
| `gd`          | перейти к определению                        |
| `gr`          | найти все использования                      |
| `gI`          | перейти к реализации (для интерфейсов)       |
| `K`           | документация по символу под курсором         |
| `<leader>rn`  | переименовать символ во всём проекте         |
| `<leader>ca`  | code action (быстрые исправления, рефакторинги) |
| `<leader>d`   | показать ошибку на текущей строке во всплывающем окне |
| `[d` / `]d`   | предыдущая / следующая ошибка                |

### Автодополнение (в Insert-режиме)

| Клавиша            | Действие                                       |
|--------------------|------------------------------------------------|
| `<C-Space>`        | вызвать меню дополнения вручную                |
| `<Tab>` / `<S-Tab>`| следующий / предыдущий вариант                 |
| `<CR>` (Enter)     | принять вариант (если ничего не выбрано - первый) |
| `<C-e>`            | закрыть меню                                   |

### Git

| Клавиша       | Действие                                             |
|---------------|------------------------------------------------------|
| `]h` / `[h`   | следующий / предыдущий изменённый кусок (hunk)       |
| `<leader>hp`  | показать diff текущего куска                         |
| `<leader>hs`  | застейджить кусок (`git add` только этого фрагмента) |
| `<leader>hu`  | отменить стейджинг куска                             |
| `<leader>hr`  | откатить кусок к версии из git                       |
| `<leader>gs`  | открыть Neogit (аналог `git status` с интерфейсом)  |

Любое сочетание можно найти через `:Telescope keymaps`.

## 5. Плагины подробно

### lazy.nvim - менеджер плагинов (`lua/config/lazy.lua`)

Каждый файл в `lua/plugins/` возвращает список "спецификаций" плагинов. Поля спецификации:

- `"автор/репозиторий"` - откуда скачать плагин с GitHub.
- `dependencies` - плагины, которые нужно поставить и загрузить раньше.
- `opts = {...}` - настройки; lazy сам вызовет `require("плагин").setup(opts)`.
  `config = true` - то же самое с пустыми настройками.
- `config = function() ... end` - своя функция настройки вместо стандартной.
- `event`, `cmd`, `keys` - ленивая загрузка: плагин загружается только при событии
  (например `InsertEnter`), команде или нажатии клавиши. Это ускоряет запуск.
- `lazy = false` - загружать сразу при старте.
- `priority = 1000` - загрузить раньше остальных (нужно теме, чтобы всё сразу было в её цветах).
- `build` - команда после установки или обновления (например, компиляция `make`).
- `branch` - какую ветку репозитория использовать.

Настройки менеджера:
- `install.colorscheme = { "tokyonight" }` - тема, которая используется во время первой установки.
- `checker.enabled = true, notify = false` - в фоне проверяет обновления, но не показывает
  уведомления. Обновления видно в `:Lazy`.
- `rocks.enabled = false` - отключена поддержка luarocks (не нужна, и без неё нет лишних требований).

`lazy-lock.json` фиксирует точные коммиты всех плагинов. Благодаря ему на другой машине
установятся те же версии. `:Lazy` открывает окно управления: `U` - обновить, `S` - синхронизировать,
`X` - удалить лишние.

### LSP и форматирование (`lua/plugins/lsp.lua`)

- **mason.nvim** - установщик внешних программ (языковых серверов, форматтеров, линтеров)
  в `~/.local/share/nvim/mason/`. Окно - `:Mason`, в нём `i` - установить, `X` - удалить.
  Mason добавляет свою папку с бинарниками в `PATH` внутри Neovim.
- **mason-lspconfig.nvim** - мост между mason и LSP. Здесь он только гарантирует, что
  `gopls` установлен (`ensure_installed`). Автоматическое включение серверов отключено
  (`automatic_enable = false`), сервер включается явно ниже.
- **nvim-lspconfig** - готовые настройки для сотен языковых серверов (какую команду запускать,
  как найти корень проекта и т.д.). Конфиг использует встроенный API Neovim 0.11:
  - `vim.lsp.config("gopls", {...})` - дополняет стандартные настройки gopls своими.
  - `vim.lsp.enable("gopls")` - включает сервер: при открытии `.go` файла gopls запустится сам.
  - `capabilities` из `cmp-nvim-lsp` сообщают серверу, что редактор умеет в расширенное
    автодополнение (сниппеты и т.п.).

  Настройки gopls:
  - `gofumpt = true` - форматирование в более строгом стиле gofumpt.
  - `usePlaceholders = true` - при дополнении функции подставляются имена параметров.
  - `completeUnimported = true` - дополнение из пакетов, которые ещё не импортированы
    (импорт добавится автоматически).
  - `staticcheck = true` - дополнительные проверки кода от staticcheck.
  - `analyses.unusedparams`, `analyses.shadow` - предупреждения о неиспользуемых параметрах
    и о переменных, которые затеняют внешние.
  - `hints` - какие inlay hints (серые подсказки типов и имён параметров прямо в коде)
    сервер готов отдавать. Показ самих подсказок в редакторе не включён (см. "Нюансы").

  Автокоманда `LspAttach` срабатывает, когда сервер подключается к буферу, и создаёт
  LSP-сочетания только для этого буфера (`buffer = event.buf`). Поэтому `gd`, `K` и
  прочие работают только там, где есть LSP.

  `vim.diagnostic.config` - как показывать ошибки: текст в конце строки (`virtual_text`),
  значки в колонке слева (`signs`), подчёркивание (`underline`), без обновления во время
  набора текста (`update_in_insert = false`).

- **conform.nvim** - форматирование. Загружается перед сохранением (`BufWritePre`).
  Для Go последовательно запускает `goimports` (сортирует и добавляет/удаляет импорты),
  затем `gofumpt` (форматирует код). Если форматтеров нет, используется форматирование
  через LSP (`lsp_fallback`). Лимит - 1 секунда. `:ConformInfo` показывает, какие
  форматтеры найдены.

### Автодополнение (`lua/plugins/completion.lua`)

- **nvim-cmp** - всплывающее меню дополнения. Загружается при первом входе в Insert-режим.
- Источники вариантов в двух группах. Вторая группа используется, только если первая
  ничего не дала:
  1. `nvim_lsp` (от gopls) и `luasnip` (сниппеты);
  2. `buffer` (слова из открытых файлов) и `path` (пути файловой системы).
- **LuaSnip** - движок сниппетов (шаблонов кода). **friendly-snippets** - готовая
  коллекция сниппетов для многих языков, в том числе Go. Например, `iferr` разворачивается
  в `if err != nil { ... }`.

### Treesitter (`lua/plugins/treesitter.lua`)

Используется новая ветка `main` плагина nvim-treesitter. Она не поддерживает ленивую загрузку,
поэтому `lazy = false`.

- `require("nvim-treesitter").install(parsers)` ставит парсеры для Go (`go`, `gomod`,
  `gowork`, `gosum`), Lua и Vim. Если парсеры уже стоят, ничего не делает.
- Автокоманда на `FileType` для этих языков включает подсветку treesitter
  (`vim.treesitter.start`) и расчёт отступов через treesitter (`indentexpr`).
  `pcall` защищает от ошибки, если парсера нет.
- `build = ":TSUpdate"` - обновлять парсеры при обновлении плагина.

### Telescope (`lua/plugins/telescope.lua`)

Нечёткий (fuzzy) поиск по чему угодно: файлам, тексту, буферам, справке, сочетаниям клавиш.

- **plenary.nvim** - библиотека утилит, нужна многим плагинам.
- **telescope-fzf-native** - быстрый алгоритм сортировки на C (компилируется через `make`).
  Подключается через `pcall`, чтобы Telescope работал даже если компиляция не удалась.

В окне Telescope: печатайте запрос, `<C-n>`/`<C-p>` или стрелки - выбор, `Enter` - открыть,
`<C-v>` - открыть в вертикальном сплите, `Esc` (в Normal-режиме окна) или `<C-c>` - закрыть.
Все доступные пикеры - `:Telescope`.

### Git (`lua/plugins/git.lua`)

- **gitsigns.nvim** - значки изменений в колонке слева (добавлено / изменено / удалено
  относительно git) и операции с отдельными кусками изменений (hunks), см. таблицу клавиш.
  `current_line_blame = false` - автор последнего изменения строки не показывается.
- **neogit** - интерфейс Git в стиле Magit (Emacs). Открывается `<leader>gs` или `:Neogit`.
  Внутри: `s` - застейджить файл/кусок под курсором, `u` - убрать из стейджа,
  `c` затем `c` - коммит (сообщение пишется в открывшемся буфере, сохранить - `:wq`),
  `P` затем `p` - push, `p` - pull, `?` - все команды, `q` - закрыть.

### Интерфейс (`lua/plugins/ui.lua`)

- **tokyonight.nvim** - тема оформления, вариант `tokyonight-night`.
- **lualine.nvim** - статусная строка внизу: режим, ветка git, имя файла, ошибки LSP,
  позиция курсора. Настройки по умолчанию.
- **neo-tree.nvim** - дерево файлов слева (`<leader>e`). Внутри: `Enter` - открыть,
  `a` - создать файл (с `/` в конце - папку), `d` - удалить, `r` - переименовать,
  `m` - переместить, `c` - скопировать, `H` - показать скрытые, `?` - все команды.
- **nvim-web-devicons** - иконки типов файлов. **nui.nvim** - UI-библиотека для neo-tree.

## 6. Требования и установка

1. **Neovim 0.11+** (`nvim --version`). Конфиг использует `vim.lsp.config` / `vim.lsp.enable`,
   которых нет в более старых версиях. Ветка `main` nvim-treesitter тоже требует 0.11+.
2. **Go** в `PATH` (`go version`).
3. **git**, **make**, компилятор C (на macOS: `xcode-select --install`).
4. **tree-sitter CLI** - нужен ветке `main` nvim-treesitter для сборки парсеров:
   `brew install tree-sitter-cli`. Без него парсеры не соберутся, и при каждом запуске
   будут ошибки `ENOENT ... 'tree-sitter'`, а Go будет подсвечиваться старой подсветкой
   на регулярных выражениях.
5. **ripgrep** для `<leader>fg`: `brew install ripgrep`.
6. Шрифт [Nerd Font](https://www.nerdfonts.com/) в терминале, иначе вместо иконок будут квадраты.

Первый запуск `nvim` сам скачает lazy.nvim и все плагины. Дождитесь окончания установки
и перезапустите Neovim.

### Инструменты Go

`gopls` ставит Mason автоматически. Форматтеры для conform нужно поставить отдельно,
любым из способов:

```
:MasonInstall goimports gofumpt
```

или

```bash
go install golang.org/x/tools/cmd/goimports@latest
go install mvdan.cc/gofumpt@latest
```

Во втором случае `~/go/bin` должен быть в `PATH`.

### Проверка, что всё работает

- `:checkhealth` - общая диагностика (можно точечно: `:checkhealth vim.lsp`, `:checkhealth nvim-treesitter`).
- `:Lazy` - состояние плагинов.
- `:Mason` - установленные инструменты.
- `:ConformInfo` - найдены ли форматтеры.
- Откройте `.go` файл в Go-модуле и нажмите `K` на любой функции - должна появиться документация.

## 7. Нюансы и известные недочёты конфига


- **`scrolloff` задан дважды.** В `options.lua` стоит `8`, но в конце `init.lua` - `999`,
  и побеждает последнее. Итог: курсор всегда в середине экрана, текст прокручивается под ним.
- **Inlay hints не отображаются.** В настройках gopls включены `hints`, но показ в редакторе
  не включён. Нужен вызов `vim.lsp.inlay_hint.enable(true)` (например в `LspAttach`).
- **Нет перехода между полями сниппета.** Благодаря `usePlaceholders` и сниппетам появляются
  поля для заполнения, но клавиши перехода по ним в LuaSnip не назначены (`<Tab>` занят
  меню дополнения).
- **Комментарий про `<leader>tb`** в `git.lua` обещает переключение blame, но само сочетание
  не создано.
- **`gr` и стандартные сочетания Neovim 0.11.** В 0.11 появились встроенные `grn`, `grr`,
  `gra`, `gri`. Из-за этого после `gr` Neovim ждёт `timeoutlen` (300 мс), нет ли продолжения.
- **Устаревшие API** (пока работают, но могут выдавать предупреждения в будущих версиях):
  `vim.loop` (новое имя `vim.uv`), `vim.highlight.on_yank` (`vim.hl.on_yank`),
  `vim.diagnostic.goto_prev/next` (`vim.diagnostic.jump`), `lsp_fallback` в conform
  (`lsp_format = "fallback"`), `undo_stage_hunk` в gitsigns (теперь повторный `stage_hunk`
  снимает стейджинг).
- **`clipboard = "unnamedplus"`** - любое удаление (`dd`, `x`) тоже попадает в системный
  буфер обмена и перезаписывает то, что вы скопировали в другой программе.
